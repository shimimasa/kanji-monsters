### 1-2. ミニゲームの 手ごたえの 音

41本とも、答えた 時の 音しか ない。共通の 小さな 音（WebAudio で その場で 作る）を 用意して、
各ゲームの ぶつかる・跳ぶ・取る・落ちる に つなぐと、手ごたえが 大きく 上がる。

- 作り方の 見本：`src/minigames/gotomonDrum/drumView.js` の `tone()`（発振器 1つ＋音量の 減衰）。
  これを `src/audio/synthSE.js` の ような 共通の 部品に して、`bounce`・`jump`・`pickup`・`pop`・`whoosh` などを 名前で 呼べるように する。
- **答えの 正誤を 音で 決めない**。音は 見た目の 演出だけ（学習記録の 公平さ）。
- 広場と ミニゲームにも それぞれ BGM を（下の 2.）。

### 1-3. 鳴らし方そのものの 改善

- いまは 効果音の たびに `new Audio()` を 作っている（`audioManager.js` の `playSE`）。スマホ（特に iPhone）では
  遅れたり 重ならなかったり しやすい。よく 鳴る 音（`tap`・`decide`・`correct`）は WebAudio に 先読み して 鳴らすと 遅れが 消える。
- 音量の 初期値は BGM・効果音 とも 0.2。設定画面で 変えられるので、そのままで よい。

## 実装の 決まり（Codex 向け）

1. **`src/audio/audioManager.js` は 2つの テストで 凍結されている**
   （`tests/gotomon-minigames/english-learning.test.mjs` と `tests/minigame-production-kanji-defense/scope.test.mjs`）。
   効果音の キーを 足すには この ファイルの `FILES.se` を 変えるので、**先に 凍結を 外す**
   （2つの テストの 一覧から `src/audio/audioManager.js` を 消し、理由を コメントに 書く）。バトル画面の 凍結を 外した 時と 同じ やり方。
2. 音の ファイルは 3形式（`.mp3`・`.m4a`・`.ogg`）を 同じ 名前で 置く。いまの 音は ぜんぶ この形。
   この PC には ffmpeg（9.0.2）が ある。Python の 標準の `wave` で 波形を 作り、ffmpeg で 3形式に できる。
   **ほかの 人の 音源を 使う 時は ライセンスを 確かめて 記録する**。
3. **間違えた 時の 音は 追い打ちに しない**。復習では 不正解音を 鳴らさない、「今回は ここまで」は 無音、の 決まりが ある
   （`reviewStage.js`・`audioManager.js` の NOTE）。`nearMiss` は はげます 音に する。
4. **答えの 正誤は 子どもが はっきり 選んだ 操作だけで 決める**。音や 演出で 決めない。
5. npm の パッケージは 足さない（足すなら 先に ユーザーに 聞く）。
6. 改行が まざった ファイルが 多い。直す 時は `python scripts/one-off/edit-keep-eol.py <file> <spec.json>` を 使い、
   `git diff --numstat` と `git diff --numstat --ignore-cr-at-eol` の 数が 同じ ことを 確かめる。
7. 終わったら `bash scripts/playtest-cdp/run-all-tests.sh` が `ALL-PASS`。コミット本文に 確かめた 数を 書く。
8. 子ども向けの 文言は 前向きに（「失敗」「不合格」「解放されていません」を 使わない）。
